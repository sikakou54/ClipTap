# パターン展開の観点

「ログイン機能 → ログインできること」で終わらせないための観点表。
各機能に当てはめ、**成立し得るもの**をすべて `pattern-matrix.csv` の行にする。
該当しない観点を無理に埋める必要はないが、埋めなかったことは
`ConditionID` を作らないという形で明示され、レビューで検査される。

---

## 1. 入力パターン

| 観点 | ClipTapでの具体例 |
|---|---|
| 正常値 | タイトル「あいさつ」 |
| 最小値 | タイトル1文字、変数名1文字 |
| 最大値（上限ちょうど） | タイトル30文字、プロファイル名20文字、カテゴリ名20文字、変数名30文字、ラベル30文字 |
| 上限+1 | タイトル31文字（画面は31文字目を受け付けない。保存層は取込互換で保持する） |
| 空文字 | タイトル空、本文空、変数値空（＝未設定として標準値へフォールバック） |
| 未入力 | 必須項目を触らずに保存 |
| 前後空白のみ | 「   」だけの名前（除去後に空になる） |
| 前後空白付き | 「 あいさつ 」（保存時に除去される） |
| 改行を含む | タイトルは改行不可、本文は改行可、変数値は複数行可 |
| 不正形式 | 変数名が数字始まり、記号を含む、システム予約名と衝突 |
| 重複 | 既存と同じカテゴリ名・プロファイル名・変数名（UNIQUE制約） |
| 大文字小文字 | システム予約名は大小を区別しない、カスタム変数同士は区別する |
| 想定外文字 | 絵文字、サロゲートペア、`<>&"`、タブ |
| 長大入力 | 本文に上限は無い。数千文字を貼り付ける |
| 未定義トークン | `{{存在しない変数}}` は展開されずトークンのまま残る |

境界値は「上限ちょうど」「上限+1」を必ず対にする。片方だけでは境界を検証していない。

## 2. 状態パターン

| 観点 | 使うfixture |
|---|---|
| 初期状態（初回起動） | `install=fresh` |
| データなし（定型文0件） | `empty-snippets` |
| データなし（カテゴリ0件） | `empty-categories` |
| データなし（カスタム変数0件） | `empty-variables` |
| データなし（プロファイル0件） | `no-profile` |
| 1件 | `single` |
| 複数件 | `baseline` |
| 上限到達（Free） | `free-limit` |
| 上限超過・無効データあり | `over-limit` |
| 境界値データ | `boundary` |
| 並べ替えの差が出るデータ | `sortable` |
| 大量データ | `many` |
| 既定以外の書式 | `formats` |
| 処理中 | 保存・インポート・購入の実行直後 |
| 成功後 | 保存直後の一覧、インポート反映後 |
| 失敗後 | パスワード不一致、チェックサム不一致、スキーマ過新 |

**画面をまたぐ状態**も状態パターンに含める。ClipTapで実際に壊れやすいのはここ。

- 画面遷移して戻ったときの選択状態（カテゴリチップ、環境チップ）
- ピッカーをキャンセルしたときに前回の編集が残っていないか
- モーダルを閉じて再度開いたときの初期値
- アクティブプロファイルを切り替えたあとの一覧の展開結果

## 3. 権限・プランパターン

ClipTapにRoleは無い。代わりに次が権限相当の軸になる。

| 軸 | 値 |
|---|---|
| プラン | Free / Pro |
| 認証 | 未連携 / Google連携 / Apple連携 |
| データの有効状態 | `valid=1`（有効） / `valid=0`（Free上限超過で無効） |
| プロファイルの位置づけ | 標準 / 非標準、アクティブ / 非アクティブ |
| OS権限 | クリップボード貼り付け許可、拡張キーボードのフルアクセス（実機のみ） |

Free / Proで挙動が変わる機能では**必ず両方**のパターンを作る。
広告の表示、上限メッセージ、Pro案内、無効バッジがこれに当たる。

## 4. 分岐パターン

ソースコードから抽出した条件へ `ConditionID` を振り、成立する組み合わせを列挙する。
機械的な直積は作らない。**挙動に差が出る組み合わせだけ**を残す。

例: タイトルのみコピー（§8.11）

| 条件 | 値 |
|---|---|
| タイトル | あり / 空文字 / NULL |
| タイトル内の変数 | なし / システム変数 / カスタム変数（有効） / カスタム変数（無効） |
| タイトル同時コピー | ON / OFF |

3 × 4 × 2 = 24 の直積のうち、タイトルがNULL・空文字のときはタップ自体が成立しないので
変数と同時コピーの軸が意味を持たない。成立するのは
`(あり) × 4 × 2 = 8` と `(空文字 / NULL) × 1 × 1 = 2` の計10パターン。
**このように「なぜその数になるのか」を `Condition` 列に書き残す。**

## 5. 画面遷移パターン

| 観点 | 確認すること |
|---|---|
| 正方向遷移 | 起点をタップして目的の画面が出る |
| 戻る | 戻ったときに元画面の状態が保たれる |
| キャンセル | 編集内容が破棄される（次回開いたときに残っていない） |
| 完了後遷移 | 保存後にどこへ戻るか、一覧へ即反映されるか |
| エラー後遷移 | 画面が残るか、戻されるか |
| 条件付き遷移 | 上限到達時にPaywallへ誘導される |
| データ状態別遷移 | 0件のときに空状態の追加導線から遷移できる |
| Modal / Stack | `presentation` の違い（modal / transparentModal / fullScreenModal / card） |
| タブレット差 | `isTabletDevice` で `card` になる画面がある |
| 多段の戻り | 3階層入ってから連続で戻る |
| Deep Link | `simctl openurl` はiOSの確認ダイアログに阻まれる。UNREACHABLEとして記録する |

**同じRouteでも起点が違えば別パターン。**
たとえばカテゴリ選択画面は「定型文編集から」と「設定のカテゴリ管理から」で
戻り先も選択後の挙動も違う。1度到達しただけでRouteテスト完了にしてはいけない。

## 6. 操作パターン

| 観点 | Action |
|---|---|
| タップ | `TAP` |
| 長押し | `LONG_PRESS`（500ms以上） |
| ダブルタップ | `DOUBLE_TAP` |
| 連続タップ・多重実行 | `TAP_REPEAT`（保存が二重に走らないか、モーダルが二重に開かないか） |
| スワイプ | `SWIPE` |
| スクロール | `SCROLL` / `SCROLL_TO` |
| プルリフレッシュ | `PULL_REFRESH`（インジケータが**戻る**ことまで確認する） |
| キーボード入力 | `TYPE` / `TYPE_RAW` |
| キーボードの表示・非表示 | 入力欄タップ後にレイアウトが崩れないか |
| 途中キャンセル | 入力途中で戻る |
| バックグラウンド化 | `HOME` してから戻る |
| 再実行 | 同じ操作を2回続ける |

## 7. 非機能・環境パターン

| 観点 | 方法 |
|---|---|
| 言語 | `locale=ja` / `locale=en` |
| 外観 | `appearance=light` / `appearance=dark` |
| オフライン | `network=off`（`config.env` の許可が必要） |
| 大量データ | `fixture=many` |
| 日付依存 | `${TODAY:yyyy/MM/dd}` で期待値を実行時に決める |

## パターンIDの付け方

```
P-<FeatureID省略形>-<連番3桁>
例: P-F02-001, P-F11-014
```

`ConditionID` は次のとおり。

```
C-<FeatureID省略形>-<連番2桁>
例: C-F02-01
```

1つの `ConditionID` に複数の `PatternID` がぶら下がる。
条件（何を変えるか）とパターン（どの値にしたか）を混ぜない。
