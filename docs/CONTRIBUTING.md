## 行動規範

### 基本原則

1. **相互尊重**: すべてのメンバーを尊重し、建設的なコミュニケーションを心がける
2. **オープン性**: 質問や提案を歓迎し、オープンに議論する
3. **品質重視**: コードの品質とユーザー体験を最優先する
4. **学習意欲**: 新しいことを学び、チームと知識を共有する

### 禁止事項

- ハラスメント、差別的な発言
- 個人攻撃や侮辱的なコメント
- 機密情報の漏洩
- スパム行為

## 貢献の種類

### 1. バグ報告

バグを見つけた場合、GitHubのIssuesで報告してください。

#### バグ報告に含めるべき情報

- **タイトル**: 簡潔で具体的なタイトル（例: 「スニペットコピー時にアプリがクラッシュする」）
- **環境情報**:
  - OS: iOS/Android
  - OSバージョン: 例）iOS 17.0
  - アプリバージョン: 例）1.0.8
  - デバイス: 例）iPhone 15 Pro
- **再現手順**: バグを再現できる具体的な手順
- **期待される動作**: 本来どうあるべきか
- **実際の動作**: 何が起きているか
- **スクリーンショット**: 可能であれば画面キャプチャを添付

#### バグ報告テンプレート

```markdown
## バグの概要
スニペットコピー時にアプリがクラッシュする

## 環境情報
- OS: iOS 17.0
- アプリバージョン: 1.0.8
- デバイス: iPhone 15 Pro

## 再現手順
1. メイン画面を開く
2. スニペット「お礼メール」をタップ
3. アプリがクラッシュする

## 期待される動作
スニペットがクリップボードにコピーされ、トーストが表示される

## 実際の動作
アプリがクラッシュし、ホーム画面に戻る

## スクリーンショット
（添付）

## エラーログ
（Xcodeのコンソールログ、またはCrashlytics等）
```

---

### 2. 機能提案

新しい機能のアイデアがある場合、GitHubのIssuesで提案してください。

#### 機能提案に含めるべき情報

- **タイトル**: 提案する機能の名前（例: 「スニペットのお気に入り機能」）
- **背景**: なぜこの機能が必要か
- **提案内容**: 具体的にどのような機能か
- **UI/UXイメージ**: 可能であればモックアップやワイヤーフレーム
- **代替案**: 他の実装方法があれば記載

#### 機能提案テンプレート

```markdown
## 提案する機能
スニペットのお気に入り機能

## 背景
よく使うスニペットをすぐに見つけたい

## 提案内容
- スニペットカードに⭐️ボタンを追加
- お気に入りに設定したスニペットは一覧の上部に表示
- お気に入り数の上限なし

## UI/UXイメージ
（モックアップ添付）

## 代替案
- フィルター機能でお気に入りのみ表示
- 専用の「お気に入り」タブを追加
```

## 開発環境のセットアップ

詳細は [DEVELOPMENT.md](./DEVELOPMENT.md) を参照してください。

### クイックスタート

```bash
# 1. リポジトリをフォーク & クローン
git clone https://github.com/YOUR_USERNAME/clipTap.git
cd clipTap

# 2. 依存関係をインストール
npm install

# 3. iOS用CocoaPodsインストール（macOSのみ）
cd apps/mobile/ios
pod install
cd ../../..

# 4. 開発サーバー起動
cd apps/mobile
npm start
```

## Gitワークフロー

ClipTapでは**Git Flow**をベースにしたワークフローを採用しています。

### ブランチ戦略

```
main          # 本番環境（App Store/Google Play）
  │
  ├─ develop  # 開発環境（次回リリース候補）
  │    │
  │    ├─ feature/add-favorite  # 新機能開発
  │    ├─ fix/copy-crash        # バグ修正
  │    └─ docs/update-readme    # ドキュメント更新
  │
  └─ hotfix/urgent-fix  # 緊急バグ修正（mainから派生）
```

### ブランチ命名規則

| 種類 | 命名規則 | 例 |
|------|---------|-----|
| 新機能 | `feature/機能名` | `feature/add-favorite` |
| バグ修正 | `fix/バグ名` | `fix/copy-crash` |
| ドキュメント | `docs/内容` | `docs/update-readme` |
| リファクタリング | `refactor/対象` | `refactor/snippet-service` |
| 緊急修正 | `hotfix/内容` | `hotfix/crash-on-startup` |

## Pull Request作成手順

### Step 1: Issueを作成（または既存Issueを確認）

PR作成前に、関連するIssueが存在することを確認してください。
存在しない場合は、Issue を作成して内容を議論しましょう。

---

### Step 2: ブランチを作成

```bash
# developブランチから最新を取得
git checkout develop
git pull origin develop

# 新しいブランチを作成
git checkout -b feature/add-favorite
```

---

### Step 3: コードを書く

#### 必ず守るべきルール

詳細は [CLAUDE.md](../CLAUDE.md) を参照してください。

**重要な原則**:
1. **Mapper経由必須**: 直接SQLを書かない
2. **型チェック必須**: `npx tsc --noEmit` でエラー0件
3. **多言語対応必須**: すべてのテキストは `i18next` 経由
4. **テーマシステム必須**: すべてのカラーは `themeSystem` 経由
5. **FlashList使用**: FlatListは使わない

---

### Step 4: コミット

#### コミットメッセージ規約

```
<type>: <subject>

<body>

<footer>
```

**type一覧**:
- `feat`: 新機能
- `fix`: バグ修正
- `docs`: ドキュメント変更
- `style`: コードフォーマット（機能変更なし）
- `refactor`: リファクタリング
- `test`: テスト追加・修正
- `chore`: ビルド設定、依存関係更新等

**例**:

```
feat: スニペットのお気に入り機能を追加

- スニペットカードに⭐️ボタンを追加
- お気に入り設定・解除機能を実装
- お気に入りスニペットは一覧上部に表示

Closes #123
```

---

### Step 5: テスト

#### 必須チェック項目

- [ ] TypeScript型チェック: `npx tsc --noEmit`
- [ ] iOS実機/シミュレーターで動作確認
- [ ] Android実機/エミュレーターで動作確認
- [ ] ダークモード対応確認
- [ ] 多言語対応確認（日本語/英語）
- [ ] オフライン動作確認

---

### Step 6: Push & Pull Request作成

```bash
# リモートにpush
git push origin feature/add-favorite
```

GitHub上でPull Requestを作成します。

#### PRテンプレート

```markdown
## 概要
スニペットのお気に入り機能を追加

## 変更内容
- [ ] スニペットカードに⭐️ボタンを追加
- [ ] お気に入り設定・解除機能を実装
- [ ] お気に入りスニペットは一覧上部に表示

## 関連Issue
Closes #123

## テスト
- [x] TypeScript型チェック (`npx tsc --noEmit`)
- [x] iOS実機で動作確認
- [x] Android実機で動作確認
- [x] ダークモード対応確認
- [x] 多言語対応確認

## スクリーンショット
（添付）

## レビューポイント
- SnippetService.tsのお気に入りロジック
- SnippetCard.tsのUI実装
```

## コードレビュープロセス

### レビュアーの責任

1. **機能確認**: 変更が意図通り動作するか
2. **コード品質**: コーディング規約に従っているか
3. **パフォーマンス**: 不要な処理やメモリリークがないか
4. **セキュリティ**: SQLインジェクション等のリスクがないか
5. **テスト**: 十分なテストが行われているか

### レビューコメントの種類

- **[必須]**: 修正必須（承認前に対応必要）
- **[提案]**: 改善提案（任意）
- **[質問]**: 実装意図の確認
- **[賞賛]**: 良い実装への評価

### レビュー例

```markdown
[必須] SnippetService.ts:45
直接SQLを実行しています。Mapper経由で実装してください。

[提案] SnippetCard.tsx:120
この処理はuseMemoで最適化できそうです。

[質問] CategoryService.ts:78
なぜこの順序でソートしているのですか？

[賞賛] VariableParser.ts:150
エラーハンドリングが丁寧で素晴らしいです！
```

## マージ基準

以下の条件をすべて満たすとマージできます：

1. ✅ 最低1名の承認（Approve）
2. ✅ TypeScript型チェック合格
3. ✅ すべてのレビューコメント対応済み
4. ✅ iOS/Android両方で動作確認済み
5. ✅ ドキュメント更新済み（必要な場合）

## リリースプロセス

### バージョニング

[Semantic Versioning](https://semver.org/) に従います。

```
MAJOR.MINOR.PATCH

例: 1.0.8
  ↑ ↑ ↑
  │ │ └─ バグ修正（1.0.7 → 1.0.8）
  │ └─── 新機能追加（1.0.0 → 1.1.0）
  └───── 破壊的変更（1.0.0 → 2.0.0）
```

### リリースフロー

```
1. develop → release/1.1.0 ブランチ作成
2. バージョン番号更新（app.json, package.json）
3. リリースノート作成
4. テスト実施（回帰テスト含む）
5. release/1.1.0 → main マージ
6. mainからタグ作成（v1.1.0）
7. EAS Build実行
8. App Store/Google Playへ提出
9. main → develop マージ（バージョン番号反映）
```

## よくある質問（FAQ）

### Q1: どこから貢献を始めればいい？

**A**: まずは以下のドキュメントを読んでください：
1. [README.md](../README.md)
2. [DEVELOPMENT.md](./DEVELOPMENT.md)
3. [CLAUDE.md](../CLAUDE.md)

その後、`good first issue` ラベルのついたIssueから始めることをお勧めします。

---

### Q2: PRのレビューに時間がかかっている

**A**: 通常1〜3営業日以内にレビューします。
1週間経ってもレビューがない場合は、PRにコメントでメンションしてください。

---

### Q3: 自分のアイデアが採用されるか知りたい

**A**: まずIssueで提案してください。
チームで議論し、フィードバックを返します。

---

### Q4: TypeScript型エラーが解決できない

**A**: 以下を確認してください：
1. `npm install` を実行済みか
2. `npx tsc --noEmit` でエラー内容を確認
3. [CODE_READING_GUIDE.md](./CODE_READING_GUIDE.md) で似た実装を参照
4. それでも解決しない場合は、PRのコメントで質問してください

---

### Q5: ドキュメントだけの貢献も歓迎？

**A**: もちろん歓迎です！
誤字脱字、説明不足、サンプルコード追加など、どんな改善でもPRを作成してください。
