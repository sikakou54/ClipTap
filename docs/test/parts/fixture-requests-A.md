# fixture追加要求（グループA: F-02 / F-03 / F-04 / F-05）

## 1. `profile-default-last`

### 必要な状態

- プロファイル5件。**標準（`isDefault=1`）が `sortOrder` の最大値を持つ**こと。
- Freeの判定順（標準優先 → `sortOrder`）で上位3件が `valid=1`、残り2件が `valid=0`。
- 例:

| id | name | isDefault | isActive | valid | sortOrder |
|---|---|---:|---:|---:|---:|
| `pf_e` | E社用 | 1 | 1 | 1 | 4 |
| `pf_a` | A社用 | 0 | 0 | 1 | 0 |
| `pf_b` | B社用 | 0 | 0 | 1 | 1 |
| `pf_c` | C社用 | 0 | 0 | 0 | 2 |
| `pf_d` | D社用 | 0 | 0 | 0 | 3 |

### 理由

機能仕様書 §8.4 の末尾に「標準が表示順の下位にある状態から上位へ切り替えると、有効なプロファイルの組み合わせが入れ替わることがある」と書かれている。
既存fixture（`baseline` / `free-limit` / `over-limit`）はいずれも標準が `sortOrder=0` のため、標準を有効なプロファイルへ切り替えても判定順の上位3件が変わらず、有効集合が入れ替わらない。
上表の状態から標準を `pf_a` へ切り替えると判定順が `pf_a, pf_b, pf_c, pf_d, pf_e` になり、`pf_e` が無効化・`pf_c` が有効化されて集合が入れ替わる。これがこの仕様文の唯一の検証手段である。

### 使うテスト

- `P-F04-900`（現在 `UNREACHABLE`。fixtureが追加されれば `REACHABLE` へ戻せる）

### 注意

このパターンは「プロファイル管理の一覧行から標準を切り替える」操作を前提としている。
現状は行の入れ子ボタンがAXツリーに独立要素として現れないため、fixtureが追加されても標準切替そのものを自動実行できない（報告の「実装側の制約」を参照）。
先に一覧行のアクセシビリティが直る前提で用意していただきたい。
